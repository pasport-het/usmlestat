# USMLE Progress + «Слова» — исходники и автотесты

Зачем это нужно: один раз среда разработки сбросилась и унесла все тесты. Здесь лежит **всё**: приложение, сервер, обёртка для GitHub Pages, виджеты и тесты. Храните этот репозиторий **приватным**.

## Что где
| Папка | Что внутри |
|---|---|
| `src/` | `Code.gs` (сервер Apps Script), `Index.html` (приложение; это и есть исходник), `widget_usmle.js` (виджет), `mascot.js`/`mascot.css` (рисунок тьютора) |
| `github/` | обёртка для GitHub Pages: `index.html`, `sw.js`, `version.json`, `manifest`, значки |
| `words/` | второй проект «Слова»: то же самое + `tests/` |
| `tests/` | все проверки USMLE Progress |

## Как выпускать версию
1. Правите `src/Code.gs` и/или `src/Index.html`, запускаете `npm test` (и `npm run test:browser`).
2. Поднимаете версию: `const VERSION` в `Code.gs`; если меняли обёртку, то `WRAP_V` в `github/index.html` **и** число в `github/version.json` (они должны совпадать, `npm run syntax` это проверяет).
3. В Apps Script вставляете `Code.gs` и `Index.html`, затем Deploy → Manage deployments → карандаш → **New version** (не «New deployment»: адрес должен остаться прежним).
4. Файлы из `github/` загружаете в репозиторий сайта (Pages).

## Как запускать проверки
```
npm install                # один раз
npm test                   # быстрый набор, без браузера (около 2–3 минут): сервер, эталоны на Python, синтаксис
npm run test:browser       # браузерный набор (Chromium из @sparticuz/chromium; долго, 10–15 минут)
npm run test:all           # всё вместе
```
Нужны Node 22 и Python 3.

## Что проверяют тесты
- **Сервер** (`test_*.js` без «ui»): права по ключу, расчёты, копии, журнал, ключ, виджет. Таблицы Google имитирует `tests/mock4.js`, это **не** настоящие Google Sheets (число, дата, часовые пояса ведут себя по-своему).
- **Эталоны** (`diff_*_run.js` + `diff_*_spec.py`): случайные сценарии считаются приложением, а потом отдельно переписанной на Python логикой по тексту правил. Расхождение значит, что ошиблось одно из двух. Каждая правка формулы должна сопровождаться правкой эталона.
- **Браузер** (`test_*_ui.js`, `test_tabbar.js`, `test_viz.js`, `test_speed.js`, `audit_ui.js`): интерфейс, жесты меню, числа на графиках (сверка с независимым расчётом из тех же данных), скорость входа (с управляемой задержкой сервера и Chart.js), читаемость (контраст по каждому тексту), вёрстка на размерах от 320 px. Данные для просмотра дизайна даёт `tests/seed_rich.js`, снимки страниц `tests/shots_all.js`.

## Подводные камни
- Безголовый Chromium без GPU отдаёт кадры анимации нерегулярно. Тесты, где важна физика, включают равномерный таймер кадров (`raf: true` в `shots.js`); на реальном телефоне кадры идут нормально.
- Ошибки, брошенные через `evaluate`, браузер считает «чужими» и обезличивает («Script error.»). Для проверки журнала ошибок код вставляют в страницу как `<script>`.
- Тесты с жестами и страницей UWorld зависят от нагрузки машины: используйте ожидание «анимация закончилась», а не фиксированные паузы.

## Что НЕ проверено автотестами (нужен ваш телефон)
Настоящий Google Диск и Sheets, уведомления на iPhone, обновление виджетов iOS, вид нижнего меню на реальном экране, работа обёртки как установленного приложения.

## Автозапуск на GitHub
`.github/workflows/tests.yml` запускает быстрый набор при каждой отправке (`push`). Браузерная часть отмечена как необязательная (`continue-on-error`): в GitHub Actions она ни разу не запускалась.
